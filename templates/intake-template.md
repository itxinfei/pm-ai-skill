## 二、六个必答

| # | 问题 | 答案 | 答不上来说明什么 |
|---|---|---|---|
| 1 | 这事多久发生一次，一次影响多少人 |  | 频率低、影响面小，多半不该做 |
| 2 | 不做会怎样，多久内会爆 |  | 说不出代价，说明是"想要"不是"必须" |
| 3 | 成功怎么量，现在这个数是多少 |  | 没基线就没法验收，上线后只能听客户说 |
| 4 | 最大风险在哪（合规、数据、权限、依赖） |  | 风险说不清，等于没评估过 |
| 5 | 有没有更便宜的做法（改规则、改流程、加人力） |  | 直接跳到做功能，通常是最贵的一步 |
| 6 | 谁维护它，出问题谁兜 |  | 没人兜的功能，上线三个月就烂在那 |

## 三、证据

不是"我觉得"，是能拿出来给人看的。

- 用户侧证据（访谈原声、工单记录、客服截图）：
- 数据侧证据（漏斗哪一步掉、时长多少）：
- 反面证据（什么现象出现，说明这个判断是错的）：

三条里只有一条有，标出来。一条都没有，这需求就是老板的直觉。

## 四、成本与代价

- 做：约多少开发人日、动几个系统、要不要数据迁移
- 不做：会持续损失什么，按月估算
- 替代方案的成本：改规则 / 加人工 / 先做一半

# 交付到飞书文档

一条链路的最后一公里。前面不管写得多好，交不出去就是半成品。

## 为什么要这一步

产品经理要的不是 `.md`，是能发到群里的飞书文档。从 Markdown 到飞书文档，很多人以为复制粘贴就行，实际会变形：

- 表格某行列数少一格，**整张表塌成一段文字**
- 标题从 h1 直接跳 h3，**目录错位**
- 列表到第三层，**被拍平成一级**
- 本地图片路径，**导入后是空图**

这四件事都不报错。文档看起来还在，结构已经烂了。

## 用法

```bash
pm-ai-skill deliver feishu 你的PRD.md
pm-ai-skill deliver feishu 你的PRD.md --doc-version v1.0 --status 草稿 --author 张三
```

输出 `你的PRD-feishu.md`，同时在终端列出必须处理的问题：

```
已生成：PRD-feishu.md
1541 字 · 4 张表 · 16 个标题 · 6 条待办

导入前处理这 3 处，否则飞书里会变形：
  1. 第 3 行标题从 h1 跳到 h4，飞书目录会错位
  2. 有一张表每行列数不一致，已按表头 3 列补齐
  3. 第 12 行是第 4 层嵌套列表，飞书导入会拍平
```

## 它替你做的三件事

| 做什么 | 为什么 |
|---|---|
| 表格按表头列数补齐 | 少一格的表格飞书直接不认 |
| 开头加元信息行（版本/状态/作者/更新） | 文档发出去，第一眼要看到这是第几版、能不能用 |
| 文内没有一级标题时补一个 | 没有标题的文档，读者不知道从哪看 |

## 它不替你做的

- **不改内容**。只动结构，一句话都不改。内容该不该发，是评审和打分那两步的事。
- **不传图片**。本地图要自己上传到图床或飞书，或者换成占位链接。
- **不保证排版好看**。结构对不等于好看，配色、字号在飞书里再调一遍。

## 导入

飞书云文档 → 新建 → 导入文档 → 选这份 `.md`。

导入后只检查两件事：表格是不是还在表格里、目录层级对不对。这两样对了，其余都能接受。

本机装了 `lark-cli` 的，可以跳过手工导入，一条命令落库：

```bash
lark-cli docs +create --doc-format markdown --content '@./PRD-feishu.md' --title '你的 PRD' --as user
```

返回里 `data.document.url` 就是文档链接。注意 `@./` 只认当前目录下的相对路径。

实测验收（2026-11-21）：`templates/prd-b2b-template.md` 走完这一步后在飞书里 4 张表全部保住、14 个二级标题层级正确、元信息行和 6 个待办框都在，没有一处拍平。

## 什么时候不用它

- 对方要的就是 Markdown（写代码仓库文档、发 issue）
- 文档三页以内，手贴更快
- 要给的是 PPT 或 Excel，那不是一个转换问题

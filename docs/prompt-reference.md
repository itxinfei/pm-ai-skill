# 提示词参考库

92 条提示词，复制就能用。前 76 条一个模块一条，第十一、十二章是给材料和给产出打分两组。把 `xxx` 和【】里的内容换成你的业务。

比 `triggers.md` 详细：triggers 是"怎么开口"，这里是"开口之后要它做什么"。

---

## 一、需求发现与优先级

### RICE 优先级
```
用 RICE 评估下面这些需求并排序：
1. xxx
2. xxx
3. xxx

输出表格：需求 / Reach / Impact / Confidence / Effort / 得分 / 排序
每一项给出取值理由。Impact 按 3/2/1/0.5/0.25 五档，不要都给 3。
Confidence 低于 80% 的，单独标出来提醒我先验证。
```

### MoSCoW
```
用 MoSCoW 给下面需求分档，目标是砍出 MVP 范围：
【需求列表】

输出四档分类，并检查：Must 占比是否超过 40%。
超过的话，告诉我哪些可以降到 Should，理由是什么。
```

### Kano 模型
```
用 Kano 给这些功能分类：
【功能列表】

对每个功能，给出：
- 分型（基本型 / 期望型 / 兴奋型 / 无差异型 / 反向型）
- 判断依据（如果不上，用户会骂还是会夸）
- 做它的优先级建议
```

### Impact-Effort 矩阵
```
把下面需求放进 Impact-Effort 四象限：
【需求列表】

输出四格：快赢（高影响低投入）/ 大项目（高影响高投入）/ 小补丁（低影响低投入）/ 直接砍（低影响高投入）
每格列出需求，并说明投放理由。
```

### JTBD
```
用 JTBD 分析用户为什么用我们的产品：
【产品描述 / 用户访谈片段】

输出：
- 用户在什么场景下"雇佣"我们完成什么任务
- 区分功能性任务 / 情感性任务 / 社会性任务
- 用户从竞品切过来的触发事件
- 3 个还没被满足的任务机会
```

### Working Backwards
```
用 Working Backwards 倒推这个产品想法：
【想法】

1. 先写一篇对外新闻稿：用户为什么在乎，别写功能，写他能得到什么
2. 再写内部 FAQ：预判 5 个最尖锐的质疑
3. 最后反推最小功能清单，区分 Must-have / Nice-to-have

新闻稿如果写不出来，直接告诉我方向有问题，别硬凑。
```

### 用户访谈解析
```
把下面的访谈记录整理成结构化结论：
【粘贴访谈文本】

输出：
- 痛点清单，按三级分级（一级=不用就活不下去，二级=难受但能忍，三级=有点不爽）
- 爽点和痒点
- 主题聚类（哪些人反复提到同一件事）
- 原声引用（保留用户原话，不要转述）
```

### 需求澄清 5 问
```
有人提了这个需求：【需求描述】

先别急着给方案，用 5 个问题帮我判断该不该做：
1. 谁提的？他的角色和话语权是什么？
2. 什么场景下遇到的问题？
3. 现在他是怎么解决的？
4. 不解决会怎样？影响多大？
5. 他期望用什么方式解决？

问完之后，给出你的判断：真需求 / 伪需求 / 需要更多信息。
```

## 二、用户调研

### 用户分层
```
帮我给产品用户分层：
【产品描述 + 现有用户数据】

输出：
- 分层维度建议（新老 / 付费免费 / 高频低频 / 场景类型）
- 每层的核心痛点和需求差异
- 每层值得做的功能方向

提醒我：不要说"给所有用户做"，那等于没做。
```

### 问卷设计
```
帮我设计一份问卷，调研目标是：【xxx】

要求：
- 15 题以内
- 避开引导性提问、双重提问、选项不穷尽
- 说明每题想测什么
- 给出样本量建议和发放渠道
- 标注哪些题是核心题、哪些是可选题
```

### 深度访谈脚本
```
帮我写一份深度访谈脚本，访谈对象是【xxx】，想搞清楚【xxx】

结构：
- 暖场 5 分钟
- 行为回溯 20 分钟（问具体场景，不问观点）
- 痛点深挖 15 分钟（5 Why）
- 验证假设 10 分钟

每个问题配追问方向。不要问"你觉得这个功能好不好"这类问题。
```

### 可用性测试
```
帮我设计一份可用性测试方案，测试任务是【xxx】：

输出：
- 招募条件（几个用户、什么背景）
- 测试任务描述（用目标语言，不引导操作路径）
- 观察指标：完成率 / 时长 / 错误数 / SUS 评分
- 记录表格模板
- 结果怎么解读
```

### A/B 测试设计
```
设计一个 A/B 测试，假设是：【xxx】

输出：
- 明确的假设表述（如果做 X，则 Y 指标会提升 Z%）
- 唯一变量是什么
- 样本量估算和计算依据
- 分流比例
- 观察周期（最少多久）
- 统计显著性判定标准
- 止损条件（什么情况下立刻停）
```

### NPS / CSAT / CES
```
帮我设计【NPS / CSAT / CES】调研：

输出：
- 问卷题目（按对应量表标准写法）
- 发放时机和渠道
- 分数怎么解读（什么算好、什么算差）
- 从分数到改进动作的闭环设计
- 推荐者 / 中立者 / 贬损者分别该问什么追加问题
```

### 焦点小组
```
帮我设计一个焦点小组方案：
主题：【xxx】
目标用户：【xxx】

输出：
- 招募条件和筛选标准
- 人数建议和理由
- 主持人提纲（开场 / 讨论 / 收尾）
- 讨论规则（怎么防止一个人主导）
- 记录和洞察提炼方法
```

### 日记研究
```
设计一个日记研究方案，研究主题是：【xxx】

输出：
- 持续天数建议
- 每天要用户记录什么（3 个问题以内）
- 记录形式（文字 / 图片 / 语音）
- 激励设计
- 数据怎么分析
```

### 卡片分类
```
帮我设计卡片分类测试：
要验证的是：【信息架构 / 导航结构】

输出：
- 卡片清单（功能/内容条目）
- 开放式和封闭式选哪个，为什么
- 参与者数量和画像
- 结果怎么解读（分组数量、命名共识度）
```

### 反馈聚类与情感分析
```
把下面的用户反馈做结构化处理：
【粘贴反馈】

输出：
- 按功能模块分组
- 每组内按情感分组（正面 / 中性 / 负面）
- 严重度分级：P0（不能用）/ P1（严重影响）/ P2（有点不爽）
- 出现频次统计
- 最该先修的 3 个问题及理由
```

### 行为数据分析
```
帮我设计埋点方案，追踪【xxx】漏斗：

输出：
- 事件定义（事件名 / 触发时机 / 携带参数）
- 漏斗每一步的对应事件
- 需要看的指标：转化率、流失率、停留时长
- 留存分析口径（第 7 天、第 30 天怎么算）
- 路径分析想回答什么问题
```

## 三、竞品与市场

### 竞品分析
```
分析【xxx 赛道】的竞争格局：

输出：
- 直接竞品 3-5 个、间接竞品 2-3 个、潜在竞品 1-2 个
- 定位象限（选两个维度，说明为什么选这两个）
- 核心功能对比矩阵
- 竞品用户在骂什么（这是机会点）
- 3 个市场空白假设

外部数据一律标注"需人工核验"，不要编。
```

### 市场空白识别
```
基于这些信息，帮我找市场空白：
【竞品情况 + 用户反馈】

输出：
- 没被满足的细分人群
- 没被解决的场景
- 大厂看不上但够养活团队的小市场
- 每个机会的验证方式
```

### 切换动力分析
```
帮分析用户为什么会从竞品切到我们：

输出：
- 切换成本拆解：学习成本 / 数据迁移成本 / 社交关系成本
- 我们能在哪一项上做到明显更低
- 用户切换的触发事件是什么
- 具体降低门槛的动作建议
```

### 市场规模估算
```
估算【xxx】的 TAM / SAM / SOM：

要求：
- 自上而下和自下而上两种算法都算一遍
- 每个假设标注来源和置信度
- 给区间不给精确数字（比如 10-50 亿，不是 32.7 亿）
- 说明哪种算法更可信，为什么
```

### 竞品功能拆解
```
逐功能对比我们和竞品：
【产品 + 竞品清单】

输出三档分类：
- 标配（不做用户会觉得你不专业）
- 差异化（做 1-2 个就够，多了浪费）
- 过度设计（竞品做了但没人在用）

每档给出判断依据。
```

### 产品定位
```
帮我写产品定位声明：
【产品 + 目标用户 + 主要竞品】

输出：
- 一句话定位：给【谁】用的、【比谁】更【什么】的【什么】
- 三个备选版本
- 每个版本的取舍是什么
- 哪个最适合现在阶段，为什么
```

### 机会解决方案树（OST）
```
帮我建一棵机会解决方案树，业务结果是：【xxx】

四层结构：
1. 业务结果（要提升哪个指标）
2. 用户机会（用户在哪个环节卡住了，列 3-5 个）
3. 解决方案（每个机会下 2-3 个方案，不要只押一个）
4. 实验验证（每个方案怎么低成本验证）

标注哪些是假设、哪些有数据支撑。
```

### 战略分析三件套
```
对这个产品/行业做战略分析：
【背景】

三部分：
1. SWOT：优势/劣势（内部）、机会/威胁（外部）
2. PESTLE：政治/经济/社会/技术/法律/环境
3. 波特五力：行业竞争/供应商议价/买家议价/替代品/新进入者

每部分最后必须落到"所以我们该怎么做"，不要画完就扔。
```

### 厂商/供应商调研
```
我们要选【xxx 系统/供应商】，帮我走完整调研流程：

七步：
1. 明确调研目的（找技术供应商 / 采购选型）
2. 找候选厂商（渠道 + 数量）
3. 初筛标准（看什么指标筛掉谁）
4. 产品演示的问题清单（每家 1-2 小时问什么）
5. 深度对比维度表
6. POC 试用方案（跑什么真实场景，验收标准是什么）
7. 选型报告结构

提醒我：别只听销售，要找他们的老客户问真实体验。
```

## 四、策略与规划

### 产品愿景
```
帮我们写产品愿景：

要求：
- 不写功能，写要让谁的生活/工作变成什么样
- 一句话，能被团队记住
- 不要"成为行业领导者"这种空话
- 给 3 个版本，说明各自适合什么阶段
```

### 项目立项完整流程
```
我们要启动新项目：【xxx】

帮我走八步：
1. 问题定义（不是"做什么产品"，是"解决谁的什么问题"）
2. 市场分析（多大、增长、竞品、我们的位置）
3. 用户研究（目标用户、现在怎么解决、痛点多痛）
4. 产品方案（MVP 是什么、和竞品差异在哪）
5. 商业测算（投入多少人钱时间、预期收入、回本周期）
6. 风险评估（最大 3 个风险、概率、影响、最坏情况能否接受）
7. 资源需求（开发/设计/PM 各几个、预算）
8. 决策建议（做不做、第一阶段目标、什么时候验证）

控制在 10 页以内，给高管看。
```

### OKR 制定
```
帮我定【xxx 季度】的 OKR：

要求：
- Objective 定性、有挑战、有方向感
- KR 可量化、有数字、有截止时间
- KR 必须是结果不是任务（"周活从 1 万到 2 万"对，"完成 10 个功能"错）
- 给 3 个 O，每个 O 配 3 个 KR
- 标注哪些 KR 需要额外数据才能定目标值
```

### 路线图规划
```
帮我排【xxx 周期】的路线图：
当前主题：【xxx】

按 Now / Next / Later 分：
- Now：1-3 个月在做，带里程碑和负责人
- Next：3-6 个月计划做，带假设
- Later：6-12 个月想做，写清方向就行，别太细

每项写清：要解决什么问题、怎么判断做成了。
```

### Sprint / 迭代规划
```
帮我做双周迭代规划：
【需求清单 + 团队配置】

输出：
- Story Point 估算（说明估算依据）
- 团队容量计算（留 20% 应对突发）
- 迭代内任务排序
- 依赖关系和风险
- 迭代目标（一句话）
```

### 赌注评估
```
评估这个项目值不值得押：【xxx】

输出：
- 预期回报（最好情况 / 最可能情况 / 最差情况）
- 成功概率和依据
- 失败代价（沉没成本 + 机会成本）
- 最大可承受损失
- 结论：押 / 不押 / 先小规模验证

提醒：别 all in，同时押 3-5 个小赌注更稳。
```

### 苏格拉底商业模式画布
```
用苏格拉底追问模式校验这个项目的商业模式：
【项目描述】

不要直接填九宫格。先对每个模块追问，比如：
- 客户细分：你说的是谁？凭什么这么认为？
- 价值主张：客户为什么为这个付钱？

追问完输出：
- 已验证假设清单（附证据）
- 待验证假设 Top 3
- 每个假设的验证方式和成本
```

### 北极星指标
```
帮我们找北极星指标：
【产品描述 + 核心价值】

输出：
- 3 个候选指标及各自的定义
- 每个候选的优缺点
- 推荐哪个，为什么
- 这个指标的拆解逻辑（往下拆成 3-5 个一级指标）

好的北极星 = 用户获得价值的次数 × 获得价值的用户数。
```

## 五、方案与设计

### 产品架构
```
基于【xxx 场景】输出产品架构：

三层：
- 表现层：用户看到什么（哪些端、哪些页面）
- 业务层：核心能力模块（每个模块解决什么）
- 数据层：数据从哪来、怎么流转、存哪

再补充：
- 核心能力 vs 可外包能力
- MVP 范围（只做主线：用户怎么来→怎么用→怎么留）
```

### User Story 拆分
```
把这个功能拆成 User Story：
【功能描述】

要求：
- 格式：As a... I want... So that...
- 每个带验收标准（Given-When-Then）
- 粒度 2-3 天能开发完
- 按优先级排序
- 标出哪些是 Must、哪些可以砍
```

### 用户旅程地图
```
帮我画用户旅程地图：
【产品 + 用户类型】

阶段：认知 → 考虑 → 注册 → 激活 → 使用 → 留存 → 推荐

每个阶段写：
- 用户做什么
- 想什么
- 情绪（高兴/中性/痛苦）
- 触点在哪
- 痛点是什么
- 机会点是什么

最后指出：哪个环节流失最多，为什么。
```

### 故事板
```
用 6 格故事板讲清楚这个场景：
【场景描述】

每格写：画面内容 + 人物在干嘛 + 说什么
用火柴人就行，重点是把场景讲明白，不要追求好看。
```

### 思维导图
```
把下面内容转成思维导图结构：
【大纲 / 需求列表】

输出：
- 缩进式 Markdown 结构
- 检查逻辑冲突（有没有互相矛盾的需求）
- 检查循环依赖（A 依赖 B，B 又依赖 A）
- 指出层级过深的地方（超过 4 层要考虑合并）
```

### 画图实操指南
```
我要画【流程图 / 用户旅程地图 / 产品架构图 / 信息架构图 / 数据流程图】，帮我讲清楚怎么画：

输出：
- 画什么（元素清单）
- 怎么排版（横轴纵轴是什么）
- 主流程和异常流程怎么区分
- 常见错误
- 推荐工具和模板
```

### Excalidraw 可视化输出
```
帮我输出可以直接粘进 Excalidraw 的结构描述：
【要画的图类型 + 内容】

输出：
- 图形元素清单（矩形/圆形/箭头，各自代表什么）
- 布局坐标建议
- 文字标签
- 连线关系

让我复制后微调就能用。
```

## 六、文档输出

### PRD 结构化教练
```
基于业务目标【xxx】写 PRD 框架：

七段：
1. 背景：为什么做
2. 目标：要达成的指标（现状 / 目标值 / 观测周期）
3. 用户故事：谁、要什么、为什么
4. 功能描述：主流程 + 异常流程 + 边界条件
5. 验收标准：怎么判断做对了
6. 数据埋点：上线后看什么
7. 风险：可能出什么问题、怎么兜

缺数据的地方留空标"待填"，不要编。
先问我业务背景，不要直接给框架。
```

### 业务案例一页纸
```
给高管写一页纸 business case，关于【xxx】：

结构：
- 一句话建议（做 / 不做 / 灰度）
- 市场机会（估算 + 标注需核验）
- 预期收益（收入 / 留存 / 成本节约，给区间）
- 需要投入（人 / 钱 / 时间）
```

### 和开发吵架的艺术


### 数据分析
```
对这份数据做分析：
【粘贴 CSV 或描述字段】

输出：
- 数据质量检查（缺失值 / 异常值 / 格式问题）
- 关键指标趋势
- 异常点及可能的业务原因
```

### 指标层级
```
帮我们搭指标层级：
【产品 + 当前在追的指标】

输出四层：

- 一级指标：3-5 个，和北极星直接相关

提醒：每个团队只追 3-5 个一级指标，多了等于没重点。
```

### HEART 框架
```
用 HEART 评估我们产品的用户体验：
【产品描述】

五个维度分别给指标：
- Happiness 满意度：NPS / CSAT 怎么测
- Engagement 参与度：使用时长 / 频次
- Adoption 采纳率：新用户激活率
- Retention 留存率：周留存 / 月留存
- Task Success 任务成功率：完成率 / 时长 / 错误数

每个维度给 2 个具体可测指标，并说明数据从哪来。
```

### AI 产品度量
```
我们的 AI 功能是【xxx】，帮我设计评估体系：

分层：
- 上线前：准确率、召回率、幻觉率、响应延迟
- 上线后：人工接管率、用户采纳率、重试率、满意度
- 业务：留存、转化、单次成本

提醒：准确率 99% 但用户不用也是白搭，要看真实使用。
```

### RICE 复盘
```
上线后复盘当初的 RICE 估算：
【当初的估算 + 实际数据】

输出：
- 逐项对比：Reach / Impact / Confidence / Effort 哪里估错了
- 偏差原因（是信息不足还是主观乐观）
- 下一轮该调整什么判断习惯
```

### PMF
```
判断我们产品有没有 PMF：
【产品 + 用户数据】

方法：
- 设计 Sean Ellis 测试题："如果不能再使用这个产品，你会多失望？"
- 判定标准：回答"非常失望"的比例是否超过 40%
- 按用户分层分别看（不同人群 PMF 可能不一样）
- 给出结论和改进方向
```

### 延迟成本
```
帮我算这个需求的延迟成本：
【需求 + 业务背景】

输出：
- 每月延迟的损失（收入 / 用户 / 机会）
- 损失怎么算的（拆解依据）
- 和另一个需求对比，哪个延迟成本更高
- 结论：该不该插队
```

## 十一、带东西来

手里有材料的时候，别只说"帮我看看"。把材料类型说清楚，能省好几轮。

#### 访谈记录

```
我做了 8 个用户的访谈，记录在下面，保留了原话：
【粘贴，不要润色】

帮我做三件事：
1. 抽出信息量最大的原声，别改写成我的口吻
2. 按主题聚类，每个主题标出几个人提到
3. 从聚类里找机会点，说清和我们现有功能差在哪

最后回答一个问题：这批材料里，我该问却没问到的是什么
```

#### 竞品截图

```
这是 xxx 三家竞品的官网/定价页/核心流程截图。
按四个维度对比：核心功能、定价结构、目标客户、明显短板。
截图看不出来的地方标"材料不足"，不要猜。

最后一句结论：哪一块值得追，哪一块不值得
```

#### 一句话想法

```
我想做个 xxx。一句话：xxx。

先别写 PRD。过三个信号：
1. 谁有这个需求，有没有真实证据（不是"老板说"）
2. 他现在怎么解决的
3. 上线后看哪个数判断成败

三个信号哪个过不了就直说，并告诉我该先干什么
```

#### 需求清单

```
这是这季度各部门提的需求共 xx 条：
【粘贴】

先分三类：真需求 / 伪需求 / 内部诉求。
再排序，说清用的什么方法和依据。
最后给一份"建议砍掉"名单，每条写清砍了会有什么后果、谁可能不高兴
```

#### 数据报表

```
这个月 xxx 从 12% 掉到 9%，同期 xxx 没动。

按顺序来：
1. 先查口径：这个数怎么算的，有没有可能口径改过
2. 再拆维度：按端 / 渠道 / 新老用户拆，看哪一块掉最多
3. 最后给三个可能原因，每个配一条验证方法

别急着给结论，先说哪个原因的可能性最大
```

#### 差评截图

```
这是最近 20 条差评：
【粘贴】

分四类：产品问题 / 服务问题 / 预期落差 / 物流。
每类给出影响面估计，以及判断：要不要改，改的话动哪一块
```

#### 上线计划

```
这是我们下周的上线计划：
【粘贴】

做一次 pre-mortem：假设半年后这个功能失败了，倒推最可能的原因。
拆成阻断项 / 重要项 / 建议项。

再加三件事：灰度规则、回滚条件、谁按开关
```

#### 立项申请

```
这是一份立项申请：
【粘贴】

按六个问题过一遍：市场有多大、为什么是我们、具体怎么做、要多少资源、什么时候回本、不做了怎么退。
每个问题标三档：写清楚了 / 只有结论没依据 / 完全没有。

最后说：能不能上会，缺哪几块
```

#### 只有 deadline

```
下个月 15 号要上 xxx，现在什么都没有。
帮我倒排：先做什么、什么时候必须定稿、哪些可以先砍。
给一个最小可交付范围，别贪全
```

## 十二、给产出打分

评审是六个人开会，打分是你一个人先判它够不够发。两者别混。

#### PRD

```
这份 PRD 打个分，能不能进评审：
【粘贴】

五项：问题定义、目标与验收、范围边界、依赖与风险、埋点。
每项 0-3 分，扣分要指出具体哪一句原文。
有一项 0 分就直接说不能发。

结论三选一：能发 / 补两处再发 / 重写。
最后列必须补的 1-3 条，每条写清改成什么样算过
```

#### 竞品分析

```
看看这份竞品分析够不够：
【粘贴】

四项：结论先行、证据可查、差距量化、动作建议。
每项 0-3 分，指出扣在哪一句。

最后说：能不能拿去给老板看
```

#### 数据复盘

```
这份复盘打几分：
【粘贴】

四项：假设明不明确、口径一致不一致、归因有没有分层、下一步具体不具体。
特别看一件事：有没有把"环比下降"当成结论
```

#### 立项材料

```
这份立项材料能上会吗：
【粘贴】

四项：市场判断、模型可信、资源匹配、风险与退出条件。
模型那项重点看：单位经济模型能不能算出来，算不出来就是 1 分以下
```

#### 访谈整理

```
这份访谈整理能直接用吗：
【粘贴】

四项：样本交代、原声摘录、聚类有据、机会可验。
重点看：有没有把用户的话概括成自己的话，概括了就丢分
```

#### 上线计划

```
这份上线计划有没有漏洞：
【粘贴】

四项：灰度规则、回滚条件、责任到人、指标观测。
有一项 0 分就不能上
```

#### 不指定类型

```
这份东西打个分：
【粘贴】

先判断是什么材料，再选对应维度。
别为了显得认真硬挑刺，能发就说能发，最多两条加分项
```

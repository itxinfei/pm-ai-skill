# 提示词参考库

> 直接复制使用，把 `xxx` 替换成你的业务内容。

## 需求优先级（RICE）
```
使用 RICE 模型评估以下需求，并按得分排序：
1. xxx
2. xxx
3. xxx
输出表格：Reach / Impact / Confidence / Effort / 得分 / 排序，并给出每一项的取值理由。
```

## JTBD 分析
```
用 JTBD 框架分析用户为什么使用我们的产品：
- 列出用户在什么场景下"雇佣"我们完成什么任务；
- 区分功能性任务、情感性任务、社会性任务；
- 找出用户从竞品切过来的触发事件和迁移成本；
- 输出 3 个未被满足的任务机会。
```

## Working Backwards
```
用 Working Backwards 方法倒推这个新功能：
【粘贴功能想法】
1. 先写一篇对外新闻稿，回答：为什么用户在乎？
2. 再写内部 FAQ，预判质疑和边界；
3. 最后反推最小功能清单，区分 Must-have / Nice-to-have。
```

## 用户研究
```
帮我设计一份针对【老功能使用率低】的问卷 + 深度访谈脚本：
- 问卷 15 题以内，避开引导性、双重提问；
- 访谈脚本 30 分钟，含暖场、行为、痛点、验证四段；
- 输出可直接发给用户的版本。
```

## 竞品分析
```
分析【XX 垂直赛道】的竞争格局：
- 列出 Top 5 直接竞品 + 2 个跨界替代者；
- 做定位象限（价格 × 目标人群）；
- 对比核心功能差异；
- 分析用户切换动力（为什么从 A 切到 B）；
- 找出 3 个市场空白机会。
外部数据请标注"需人工核验"。
```

## 产品架构
```
基于【B 端 SaaS 客服系统】场景，输出产品业务架构：
- 表现层（用户端 / 管理端 / 开放 API）；
- 业务层（核心能力模块）；
- 数据层（埋点 / 业务库 / 数仓）；
- 区分核心能力与可外包能力；
- 拆出 MVP 范围。
```

## User Story 拆分
```
把这个功能拆成 User Story：
【粘贴功能描述】
要求：
- 格式：As a... I want... So that...；
- 每个 Story 带验收标准（Given-When-Then）；
- 粒度控制在 2-3 天可完成；
- 按优先级排序。
```

## PRD 辅助
```
基于业务目标：【提升新用户首单转化 15%】，生成 PRD 结构化框架：
- 背景与问题；
- 成功指标（现状、目标值、观测周期）；
- 非目标（本期不做什么）；
- 主流程 + 异常流程 + 边界条件；
- 回退条件与灰度计划。
不要编造业务数字，缺数据的地方留空让我填。
```

## 业务案例一页纸
```
给高管写一页纸的 business case，关于【XX 功能】：
- 一句话决策建议（做 / 不做 / 灰度）；
- 市场机会（用估算，标注"需核验"）；
- 预期收益（收入 / 留存 / 成本节约，给区间）；
- 竞品对比一句话；
- 主要风险和缓解措施。
控制在 300 字以内。
```

## 发布说明
```
帮我写一版发布说明：
- 新功能：A（一句话说清用户能干嘛）；
- 优化：B（解决了什么痛点）；
- 修复：C（不写技术细节，写用户感受）；
用用户语言，不要技术术语，控制在 200 字以内。
```

## 会议纪要
```
把下面会议录音转写文本整理成结构化纪要：
【粘贴文本】
输出：
1. 会议元信息；
2. 决策表（编号 / 决策 / 上下文 / 拍板人）；
3. 行动项表（编号 / 内容 / 负责人 / 截止时间 / 优先级）；
4. 待确认项；
5. 下次会议建议议程。
```

## 风险与延期沟通
```
项目要延期 2 周，原因是【第三方接口延迟】，帮我写沟通文案：
- 给老板：说清影响、补救方案、下一步；
- 给客户：说清原因、新时间、补偿方案；
- 语气透明、不甩锅、给解决方案。
```

## 商业模式画布（苏格拉底式）
```
用苏格拉底追问模式校验这个创新项目的商业模式：
【粘贴项目描述】
不要直接填空，先对每个模块追问，最后输出：
- 已验证假设清单；
- 待验证假设 Top 3；
- 对应的验证方式和成本。
```

## 路线图规划
```
帮我排下季度路线图：
当前有这些主题：【xxx】
按 Now / Next / Later 分：
- Now：本季度必须做，带里程碑；
- Next：下季度做，带假设；
- Later：探索中，不急；
每格写清目标和验证方式。
```

## 项目复盘六段法
```
用六段法复盘这个项目：
1. 背景：当时为什么做；
2. 角色：我在其中承担什么；
3. 决策：做了哪些关键选择，为什么；
4. 推演：当时怎么想的；
5. 结果：实际数据和结果；
6. 方法论：下次复用什么，避免什么。
标注证据等级（事实 / 推断 / 事后诸葛亮）。
```

## 数据分析
```
对这份 CSV 做数据健康检查 + 趋势 / 异常分析：
【粘贴 CSV 或描述字段】
输出：
- 数据质量（缺失 / 异常 / 格式）；
- 关键指标趋势；
- 异常点与业务解读；
- 下一步建议分析方向。
```

## AI 产品度量
```
我们做了一个 AI 客服机器人，帮我设计评估指标体系：
- 效果指标（准确率、人工接管率、解决率）；
- 体验指标（用户满意度、响应时长、重试率）；
- 业务指标（留存、转化、工单成本）；
- 成本指标（单次调用成本、GPU 利用率）；
区分上线前评测和上线后监控。
```

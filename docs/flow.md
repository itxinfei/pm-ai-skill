# 一条命令跑完半条链路

体检 → PRD → 飞书，三个文件一次生成。

```bash
pm-ai-skill flow "会员积分体系"
```

默认放在 `flow-会员积分体系/` 下，也可以 `--out` 指定。C 端小需求加 `--type light`，换轻量模板。

## 生成什么

| 文件 | 干什么 | 谁填 |
|---|---|---|
| `01-intake.md` | 需求体检卡：六个必答、证据、成本、红线、结论 | 你和 AI 一起，答不上来的留着 |
| `02-prd.md` | PRD 骨架：正文是填写提示，顶部有 15 项填写进度 | 填完勾掉，跳过的地方就是会上会被问住的 |
| `03-prd-feishu.md` | 飞书导入稿：表格已对齐、标题不跳级、带元信息行 | 不用填，直接导入 |

## 它不写内容

这一步只做机械活：文件命名、章节结构、进度清单、飞书结构校验。内容写什么，是 AI 和你的事。所以三份文件里没有一句话是编出来的结论。

有人会问：那要它干什么，我自己建个空文档不就行了。差别在于——

- 骨架里每章下面的正文是**填写提示**，写着"常见坑：只写正向流程，异常不写，上线必出事故"。空文档没有这些
- 进度清单让填到哪一眼可见，不用翻全文
- 飞书稿的结构已经校验过，不会导入完才发现表格塌了

## 一条链路怎么走

```
一句话需求
  ↓ flow 生成三份
体检卡：先问该不该做
  ↓ 结论选"做"
PRD 骨架：按章填
  ↓ 填完
飞书稿：结构校验后导入
```

按体检卡的结论来。体检写着"不做"，就不用往下填 PRD，省掉一整轮白工。这是这条链路最值钱的地方——它允许你在第一步就停。

## 什么时候不用它

- 需求已经很熟，直接写 PRD 就行，跳过体检
- 交付物不是文档（PPT、Excel、原型），这条链路不管
- 只要一份周报或会议纪要，`template` 命令取模板更快

# 打分：把 27 条用例变成可复现的分数

原来这 27 条只有一句"应当出现的行为"，谁看谁算，两个人数不一样。现在能机检的部分已经固化成规则，同一份输出跑两次一个分，换一版 skill 再跑，分数能对比。

## 怎么跑

三步，别跳：

1. 把用例的 `input` **原样**发给装了 skill 的 AI。改一个字就测不出分诊
2. 把回答存成 `<case-id>.md`，比如 `chain-001.md`
3. 打分

```bash
pm-ai-skill score chain-001 chain-001.md      # 一条，看逐条证据
pm-ai-skill score all ./answers                # 整目录批量，出通过率
pm-ai-skill score all ./answers --json         # 出 JSON，和上一版对比
```

批量只扫 `<case-id>.md` 或 `.txt`，没跑到的会单独列出来，不会当成 0 分。

## 输出长什么样

```
route-001  3/3  100%  通过

  ✓ 第一段出现明确结论  —— 首段含「不建议」
  ✓ 给出判断依据  —— …三个理由：现在每月只有 12 单…
  ✓ 不产出 PRD 章节结构  —— 没出现
```

每条都带证据：命中的回一段原文，没命中的直接说"没出现：因为 / 原因 / 依据"。

## 判定档

| 比例 | 判定 |
|---|---|
| 100% | 通过 |
| ≥70% | 勉强 |
| <70% | 不过 |

分诊类（`route-*`）挂掉最严重。分错类型，后面全错，它掉一分比别的掉三分更值得修。

## 规则能判什么，判不了什么

能判：关键词在不在、有没有套话、首段有没有结论、结构有没有跑偏、有没有编数字、篇幅是否失控。

判不了：判断得对不对、理由站不站得住、语气合不合适。这类还得人看。

所以输出里会老实写一行 `机检覆盖 3/3 项人工判据`，或者 `机检覆盖 2/3 项，剩下 1 项还得人看`。缺一条就说缺一条，不假装全覆盖。

## 拿这个分数干什么

- **回归**：改了 `system-prompt.md`，同一批答案重跑，分数掉了说明改坏了
- **对比**：两版 skill 或两个模型，跑同一批输入，看哪组规则掉得多
- **定位**：按类别看平均分，`表达` 类掉了就是措辞问题，`边界与诚实` 掉了就是敢不敢说不知道

规则本身也能挑刺：哪条规则你觉得判得太松，改 `evals/cases.json` 的 `auto` 字段，跑 `node scripts/check.js` 会校验规则写没写对。

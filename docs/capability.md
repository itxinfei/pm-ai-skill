# 能力清单

76 个模块，分 10 类。每个模块写清楚：什么时候用、输出什么。

---

## 一、需求发现与优先级（8 个）

| 模块 | 什么时候用 | 输出 |
|---|---|---|
| RICE 优先级 | 需求多、要排先后 | 每个需求的分数和排序，附带 Reach/Impact/Confidence/Effort 拆解 |
| MoSCoW 优先级 | 要砍 MVP 范围 | Must/Should/Could/Won't 四档，明确砍哪些 |
| Kano 模型 | 判断哪些功能是惊喜、哪些是底线 | 五类分型（基本/期望/兴奋/无差异/反向） |
| Impact-Effort 矩阵 | 快速脑暴，一眼看排序 | 四象限：快赢、大项目、小补丁、直接砍 |
| JTBD | 想搞懂用户为什么用你 | 用户要完成的功能性/情感性/社会性任务 |
| Working Backwards | 新功能还没想清楚 | 新闻稿 + FAQ + 反推的功能清单 |
| 用户访谈解析 | 手上有一堆访谈记录 | 痛点分级（一/二/三级）、爽点、痒点、主题聚类 |
| 需求澄清 5 问 | 有人提了个需求你要判断 | 五个问题的答案，判断这个需求到底该不该做 |

要点提醒：Must 不超过总需求的 40%，否则等于没排优先级。Impact 别拍脑袋给 3 分。

## 二、用户调研（11 个）

| 模块 | 什么时候用 | 输出 |
|---|---|---|
| 用户分层 | 做功能前先想清楚给谁做 | 新/老、付费/免费、高频/低频的分层方案 |
| 问卷设计 | 要定量验证 | 15 题以内的问卷，含样本量估算 |
| 深度访谈脚本 | 要定性挖需求 | 探索/验证两套脚本，含 5 Why 追问 |
| 可用性测试 | 验证界面能不能用 | 测试任务、观察指标、SUS 评分表 |
| A/B 测试设计 | 验证改动是否有效 | 假设、变量、样本量、观察周期、止损条件 |
| NPS / CSAT / CES | 衡量满意度和忠诚度 | 问卷设计 + 分数解读 + 改进闭环 |
| 焦点小组 | 要集体讨论出洞察 | 招募条件、主持人提纲、讨论规则 |
| 日记研究 | 要看真实使用场景 | 7-14 天的记录方案和每日问题 |
| 卡片分类 | 验证信息架构 | 开放/封闭式方案，分组结果解读 |
| 反馈聚类与情感分析 | 有一堆用户反馈要处理 | 按功能分组 + 情感分组 + P0/P1/P2 严重度 |
| 行为数据分析 | 要看用户实际怎么用 | 埋点方案、漏斗流失、留存曲线、路径 |

要点提醒：可用性测试 5 个用户能发现 80% 的问题。A/B 一次只测一个变量。

## 三、竞品与市场（9 个）

| 模块 | 什么时候用 | 输出 |
|---|---|---|
| 竞品分析 | 要摸清竞争格局 | 直接/间接/潜在三类竞品、定位矩阵、功能差异 |
| 市场空白识别 | 找切入点 | 没被满足的细分人群和场景 |
| 切换动力分析 | 想让用户从竞品过来 | 学习成本/数据迁移/社交关系的降门槛方案 |
| 市场规模估算 | 要判断这个市场值不值得做 | TAM/SAM/SOM 区间（不给精确数字），标注假设来源 |
| 竞品功能拆解 | 要知道哪些功能必须做 | 标配/差异化/过度设计三档 |
| 产品定位 | 一句话说清我们是谁 | 目标人群 + 差异化价值 + 对比优势 |
| 机会解决方案树（OST） | 有一个业务结果要实现 | 结果→机会→方案→实验四层树 |
| 战略分析三件套 | 做长期规划或行业判断 | SWOT + PESTLE + 波特五力，每个都落到结论 |
| 厂商/供应商调研 | B 端要选系统或供应商 | 7 步流程：目的→候选→初筛→演示→对比→POC→选型报告 |

要点提醒：TAM 给 10-50 亿这种区间，别写 32.7 亿。选供应商别只听销售，找他们老客户问。

## 四、策略与规划（8 个）

| 模块 | 什么时候用 | 输出 |
|---|---|---|
| 产品愿景 | 团队方向不一致 | 一句长期方向声明，不写功能 |
| 项目立项完整流程 | 要从 0 到 1 启动新项目 | 8 步：问题定义→市场→用户→方案→测算→风险→资源→决策 |
| OKR 制定 | 季度目标定不下来 | Objective + 可量化的 KR |
| 路线图规划 | 要排半年到一年的事 | Now / Next / Later 三档 |
| Sprint / 迭代规划 | 双周迭代排期 | Story Point、容量、依赖关系、风险 |
| 赌注评估 | 要不要押这个项目 | 预期回报、成功概率、失败代价、最大损失 |
| 苏格拉底商业模式画布 | 校验商业模式站不站得住 | 九个模块 + 已验证/待验证假设清单 |
| 北极星指标 | 团队不知道追什么指标 | 一个代表核心价值的指标 + 拆解 |

要点提醒：OKR 的 KR 是结果不是任务，"完成 10 个功能"是错的，"周活从 1 万到 2 万"才对。

## 五、方案与设计（7 个）

| 模块 | 什么时候用 | 输出 |
|---|---|---|
| 产品架构 | 要拆系统怎么搭 | 表现层/业务层/数据层 + MVP 范围 |
| User Story 拆分 | 要拆成可开发的粒度 | As a... I want... So that... + Given-When-Then 验收 |
| 用户旅程地图 | 要找哪个环节流失最多 | 阶段、触点、情绪曲线、痛点、机会点 |
| 故事板 | 早期概念验证 | 6 格火柴人叙事 |
| 思维导图 | 理清需求关系 | 结构化大纲 + 逻辑冲突和循环依赖检查 |
| 画图实操指南 | 不知道图该怎么画 | 流程图/旅程图/架构图/信息架构/数据流程图的画法 |
| Excalidraw 可视化输出 | 要直接出图 | 可粘贴到 Excalidraw 的结构描述 |

要点提醒：拆到 2-3 天能开发完的粒度。画图追求讲清逻辑，不追求好看。

## 六、文档输出（5 个）

| 模块 | 什么时候用 | 输出 |
|---|---|---|
| PRD 结构化教练 | 要写需求文档 | 背景/目标/用户故事/功能/验收/埋点/风险七段 |
| 业务案例一页纸 | 要给高管汇报 | 市场/做什么/投多少/赚多少/一句话建议 |
| 发布说明 | 要告诉用户更新了什么 | 用户语言写的更新文案，不写技术术语 |
| 功能规格说明 | 要给开发讲清边界 | 前置条件、主流程、异常流程 |
| 需求评审准备 | 明天要开评审会 | 议程、讲解顺序、可能被问到的问题和答法 |

要点提醒：PRD 讲"为什么做"和"做什么"，不写"怎么做"。异常流程比主流程重要。

## 七、协作与沟通（9 个）

| 模块 | 什么时候用 | 输出 |
|---|---|---|
| 会议纪要 | 开完会要留记录 | 决策 + 行动项 + 负责人 + deadline |
| 风险与延期沟通 | 项目要延期或出问题 | 原因/影响/补救方案/需要的支持 |
| 问题追踪与升级 | 问题推不动要往上捅 | issue 追踪表 + 升级邮件 |
| 销售赋能 | 销售不知道怎么卖 | 竞品 FAQ、10 个常见异议话术、Demo 脚本 |
| 干系人地图 | 不知道该怎么和各路人沟通 | 影响力×关注度四象限 + 沟通策略 |
| Pre-mortem 预先分析 | 上线前要排风险 | 老虎/纸老虎/大象三类风险清单 |
| 增长飞轮 | 想设计可持续增长 | 获取→使用→产生价值→带来新用户的循环 |
| 用户画像 | 团队对用户认知太模糊 | 2-3 个具体人物画像 |
| 和开发吵架的艺术 | 排期谈不拢 | 怎么从"做不完"聊到"怎么调整范围" |

要点提醒：纪要是决策记录不是逐字稿。坏消息早说。

## 八、数据与度量（7 个）

| 模块 | 什么时候用 | 输出 |
|---|---|---|
| 数据分析 | 有一份 CSV 要看出问题 | 数据健康检查、趋势、异常点、业务解读 |
| 指标层级 | 指标太多抓不住重点 | 北极星→一级(3-5个)→二级→护栏指标 |
| HEART 框架 | 要量化用户体验 | 满意度/参与度/采纳率/留存/任务成功率五维 |
| AI 产品度量 | 做了 AI 功能要知道好不好 | 准确率、人工接管率、满意度、成本/次 |
| RICE 复盘 | 上线后要校准判断 | 当初估算 vs 实际数据，找出哪里估错 |
| PMF | 判断产品有没有找到市场 | Sean Ellis 测试，看"非常失望"比例是否超 40% |
| 延迟成本 | 要判断某个需求晚做的损失 | 按月的损失量化，用于排优先级 |

要点提醒：先有业务问题再看数据。AI 功能准确率 99% 但没人用也是白搭。

## 九、商用与增长（7 个）

| 模块 | 什么时候用 | 输出 |
|---|---|---|
| 定价策略 | 要定怎么收费 | Freemium/订阅/按量/分层等多方案对比 + 推荐 |
| AARRR 增长漏斗 | 要找增长瓶颈 | 获取→激活→留存→变现→推荐各环节数据诊断 |
| RARRA 留存优先 | 早期产品不知道怎么排优先级 | 从留存反推的产品优先级 |
| 单位经济模型 | 判断商业模式跑不跑得通 | LTV、CAC、回本周期、毛利率 |
| GTM 上市策略 | 产品要上市 | 目标人群、渠道、定价、首发节奏、冷启动 |
| 客户成功与续费 | 要降低流失、提升续费 | 健康分模型、流失预警规则、续费话术 |
| 项目复盘六段法 | 项目结束要沉淀 | 背景/角色/决策/推演/结果/方法论 |

要点提醒：定价至少给两个方案对比。复盘要标注证据等级，别拍脑袋下结论。

## 十、自我迭代与成长（5 个）

| 模块 | 什么时候用 | 输出 |
|---|---|---|
| 使用反馈学习 | 每次输出后 | 追问哪里需要调整，分类记录偏好 |
| 个人案例库积累 | 项目做完 | 案例卡：背景/选择/决策/结果/下次复用什么 |
| 能力成长追踪 | 想知道自己短板在哪 | 用了哪些模块、哪些没用过、下一步学什么 |
| 错误复盘与修正 | 你说"这个不对" | 追问根因，不只改这一次 |
| 提示词自我优化 | 觉得输出风格不对 | 建议怎么调 system-prompt，改之前先问你 |

要点提醒：这不是一次性工具，你反馈越多它越准。案例积累会脱敏。

## 怎么选模块

不确定该用哪个？按你现在卡在哪一步挑：

- 有人说要做个功能，你不知道该不该做 → **需求澄清 5 问**
- 一堆需求排不出先后 → **RICE** 或 **Impact-Effort**
- 不知道用户到底要什么 → **深度访谈** + **JTBD**
- 不知道竞争对手在干嘛 → **竞品分析** + **竞品功能拆解**
- 要启动新项目 → **项目立项完整流程**
- 要写文档了 → **PRD 结构化教练**
- 上线前怕出事 → **Pre-mortem**
- 上线后不知道效果 → **指标层级** + **RICE 复盘**
- 产品要不要收费、怎么收 → **定价策略** + **单位经济模型**
- 想让自己下一轮更准 → **错误复盘** + **个人案例库**

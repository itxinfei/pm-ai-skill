# 行为回归用例

27 条。每条是一个输入加几条应当出现的行为，不是标准答案，是对"有没有跑偏"的最低要求。

改过 `skill-source/system-prompt.md` 之后跑一遍。改了什么，重点看对应那几条。

> `scripts/check.js` 只查结构（文件在不在、数量对不对），不管行为。这 27 条管行为，两者不互相替代。

## 怎么跑

```bash
pm-ai-skill eval            # 列出 27 条
pm-ai-skill eval route-001  # 看单条全文
```

人工回归三步：

1. 把 `input` 原样发给你装了 skill 的 AI 工具。别改字，改字就测不出分诊。
2. 对着 `checks` 逐条看输出。满足几条算几条，不要用"整体感觉还行"代替。
3. 记下哪条没满足，回到 `system-prompt.md` 找对应规则，看是规则没写清还是模型没执行。

## 自动评分

`checks` 是给人看的判据，`auto` 是同一批判据的可机检版本。把回答存成 `<case-id>.md` 后：

```bash
pm-ai-skill score chain-001 chain-001.md   # 一条，逐项给证据
pm-ai-skill score all ./answers            # 整目录，出通过率
pm-ai-skill score all ./answers --json     # 出 JSON，两版对比
```

规则类型只有七种（`has` / `hasAny` / `not` / `first` / `maxChars` / `minChars` / `maxCount`），写在 `cases.json` 的 `auto` 字段。改完跑 `node scripts/check.js`：它会编译每条正则，并拿一坨套话试一遍，规则太松的用例会被拦下。

## 判定

| 结果 | 标准 |
|---|---|
| 过 | checks 全中 |
| 勉强 | 中大半，但有一条明显偏了 |
| 不过 | 前两条里有一条没中，或输出跟 expected 反着来 |

分诊类（route-*）的"不过"最严重。分错类型，后面全错。

## 接模型批量跑

一条一条发太慢，可以把整组塞给一个模型做裁判。用这个模板：

```
你是评测员。下面是用例和一段 AI 输出。
逐条判断输出是否满足 checks，只回答"中"或"没中"，并引用输出里对应的原句作为证据。
没有证据的一律算没中。

用例：{id}
输入：{input}
应当出现：{expected}
检查项：{checks}

待评输出：
{output}
```

判定要严。模型当裁判有讨好倾向，喜欢给"基本满足"；要求它引原句，能压住一部分。

| 组 | 条数 | 测什么 |
|---|---|---|
| 分诊路由 | 4 | 判断类、产出类、链路类分得对不对 |

| 边界与诚实 | 3 | 要准确数字、要保证效果、问到权限外的事，怎么答 |
| 表达 | 2 | 有没有模板腔、翻译腔 |
| 数据与度量 | 2 | 指标异动是分层归因还是直接给结论 |
| 用户调研 | 1 | 提纲里的问题带不带倾向 |
| 竞品与市场 | 1 | 会不会只抄表面功能 |
| 自我迭代 | 1 | 复盘是具体到事，还是套话 |

哪一组挂了，就知道是哪个模块出的问题，不用整份重读。

先别急着写。"会员体系"这个词至少对应三种完全不同的东西——**付费订阅会员卡**（花钱买权益，如京东 PLUS）、**成长等级**（不花钱，按消费/行为升级，如航司银卡金卡）、**积分体系**（攒分兑换抵扣）。方向没定就动笔，写出来的只是模板填空，评审会第一轮就会被打回来。

现在我手上零背景，需要你先答这几组问题，知道多少说多少，答不上来的我标成"待确认项"，不替你编：

**必答（决定 PRD 怎么写）**

1. **产品是什么**：App / 小程序 / Web？To C 还是 To B？现在靠什么赚钱（卖货、卖服务、卖订阅、免费+广告）？大概用户量级？
2. **为什么要做、需求从哪来**：数据下滑（哪个数）、老板要求、竞品都有、用户在问？想解决的是拉新、留存、复购、客单价还是付费转化？
3. **想要哪种会员**：付费订阅 / 成长等级 / 积分 / 组合。拿不准就描述你的业务场景，我给判断和取舍。
4. **上线后看哪个数算成功**：比如会员续费率、会员 vs 非会员复购率差、付费转化率、ARPU 提升——说不出这个数，PRD 的验收标准没法写。

**有的话一起给（影响方案边界）**

5. 现状：有没有现成登录体系、历史积分/等级数据要迁移？
6. 权益成本谁承担（自家出 / 供应商谈 / 预算多少）、有没有死工期？

**答完之后的走法（链路报价，你可以随时砍步或喊停）**

| 步骤 | 交付物 | 需要你拍板的点 |
|---|---|---|
| ① 需求体检 | 体检卡 + 风险清单，结论可能是"先别做"或"有更便宜的做法" | 做/不做 |
| ② PRD | 背景目标、用户故事、主流程+异常流程、验收标准、风险 | 范围与优先级 |
| ③ 埋点方案 | 事件表，支撑第 4 题的成功指标 | 指标口径 |

先说结论：现在只有"DAU 跌了 15%"一个数，任何归因都是猜。数据掉了的正确顺序是**先确认是不是真跌，再拆维度，最后提假设验证**。下面按这个走，你把能给的数据补上。

## 第一步：先查口径，排除"假跌"（今天就能查）

这四件事不查清楚，后面全白干：

1. **统计口径变没变**：埋点 SDK 有没有升级、数据团队有没有改过 DAU 定义或去重逻辑、报表管道有没有延迟或故障
2. **对比基线是什么**：环比昨天、同比上周同一天、还是同比上月？周末/节假日/发版日的自然波动有没有排除
3. **是全端还是单端**：iOS / Android / Web / 小程序分开看，是不是某一端崩了把总数拉下来
4. **15% 是哪天开始的、跌了几天**：单日跳水还是连续阴跌，形态不一样原因完全不同

## 第二步：拆维度，定位跌在哪类人身上

拿近 14 天（含下跌前一周）的数据，按这几个维度切：

| 拆法 | 看什么 |
|---|---|
| 新用户 vs 老用户 | 新用户少了 = 渠道/投放/上架问题；老用户不回来了 = 产品或留存问题 |
| 渠道/来源 | 是不是某个投放渠道停量、应用商店排名掉了、推送触达率降了 |
| 平台/版本/机型 | 集中在某个 App 版本 → 大概率是发版引入的 bug 或崩溃 |
| 地域 | 集中在个别省市 → 可能是当地网络、监管、运营商问题 |
| 登录态/核心功能 | 登录成功率、启动成功率、崩溃率有没有同步异常 |

## 第三步：带着假设去验证，常见原因就这几类

拆完维度，大概率落到下面某一条，按概率排：

1. **技术故障**（最常见、最好查）：崩溃率、接口错误率、启动耗时、推送到达率，对着下跌起始时间点查监控和发版记录
2. **渠道侧**：投放预算调整、商店下架/审核、买量素材衰退、自然量排名下跌
3. **产品侧**：最近有没有改版、改了推送策略、登录流程、签到/活动到期
4. **外部因素**：竞品搞活动、节假日效应、社会热点分流
5. **数据本身**：回到第一步，口径或管道问题

## 你需要给我的东西

最少给这三样，我就能帮你把归因从猜变成有依据的判断：

1. 下跌前后至少 14 天的**每日 DAU 明细**（含分端）
2. 同周期的**新老用户拆分、崩溃率、渠道分布**
3. 下跌起始日前后的**发版记录和运营动作**（上线了什么、停了什么活动、投放有没有变）

另外两个关键信息先口头回我：**这是什么产品（工具/电商/内容/游戏）**，以及 **15% 是对比哪个基线**。

# 先说缺什么

你只给了一句话，下面四样关键材料都没有，实验方案里的数字我不编：

1. **新首页改了什么**——是改布局、改推荐内容、改入口位置，还是整页重做？改的东西越多，越要先拆变量，否则实验跑完也不知道是哪个改动起的作用。
2. **成功看哪个数**——新首页想拉动什么？点击率、转化率、留存、人均时长？主指标只能有一个，以及这个指标当前的基线值。
3. **流量盘子**——首页日均 UV 多少，决定样本量够不够、实验要跑多久。
4. **实验对象**——全量用户，还是只给新用户/某类用户看？

下面先给你一份可以直接填的完整骨架，所有需要业务数字的位置都标了【待填】。你把这四个数补来，我帮你算样本量和周期。

# 新首页 A/B 实验方案（骨架版）

## 1. 实验假设

- **背景假设**：用户在旧首页【待填：哪个环节】流失/找不到想要的内容，原因是【待填：具体问题，最好有用户反馈或漏斗数据支撑】。
- **H0（原假设）**：新首页对主指标没有影响，两组指标无显著差异。
- **H1（备择假设）**：新首页使【主指标】从【基线值】提升到【目标值】，即相对提升 ≥【MDE，待填】%。

## 2. 变量与版本（一次只测一个变量）

| 版本 | 内容 | 流量占比 |
|---|---|---|
| 对照组 A | 线上旧首页，原样不动 | 50% |
| 实验组 B | 新首页，仅包含【待填：本次要验证的那一处改动】 | 50% |

**如果新首页同时改了布局、推荐逻辑、入口三处**：这是整体改版测试，结论只能回答"整页换了好不好"，回答不了"谁的功劳"。要归因就拆成多轮实验，或用多变量测试（MVT），但 MVT 对流量要求更高。

## 3. 指标体系

| 类型 | 指标 | 说明 |
|---|---|---|
| 主指标（只许一个） | 【待填，如：首页到下单的转化率】 | 实验成败只看它 |
| 辅助指标 | 模块点击率、人均停留时长、次留 | 用来解释主指标为什么变 |
| 护栏指标 | 崩溃率、首页跳出率、客诉量、支付成功率 | 不允许为了主指标牺牲的底线 |

## 4. 分流规则

- **分流单位**：用户 ID 哈希，不用设备 ID（避免换设备串组）；同一用户实验期内永远进同一组。
- **分流比例**：A:B = 50:50，先按【待填：新用户/老用户/全量】分层后再哈希，保证两组人群结构一致。
- **互斥**：如果同期还有别的实验在跑，确认流量池互斥，避免污染。
- **AA 前置验证**：正式实验前先跑 2–3 天 AA（两组都看旧首页），确认两组在主指标和人群构成上无显著差异，分流无偏再开实验。

## 5. 样本量（给公式，不编数字）

实验前必须先算出每组需要多少样本，**不能跑到哪算哪**。

- 主指标是**比率型**（如转化率，对照组基线 p，想检出的最小绝对提升 Δ）：

  每组样本量 n ≈ 16 × p × (1−p) ÷ Δ²

- 主指标是**连续型**（如人均时长，对照组标准差 σ，想检出的最小提升 Δ）：

  每组样本量 n ≈ 16 × σ² ÷ Δ²

（系数 16 对应显著性水平 α=0.05、统计功效 80% 的双侧检验近似值。）

**需要你给**：基线 p（或 σ）、你能接受的最小可检测提升 MDE。MDE 定得越小，所需样本量越大——比如转化率从 10% 提升到 10.5%（Δ=0.5 个百分点），每组大约需要 5.8 万样本；想检出 0.2 个百分点的差异，每组要约 36 万。**这些数请按你的真实基线核验，我只给算法。**

## 6. 实验周期

- 周期 = 每组所需样本量 ÷ 每组日均进组用户数，**向上取整到完整自然周**。
- 硬性下限：**至少 7 天，覆盖一个完整周**（工作日和周末行为差异大），常规跑 1–2 周。
- 实验期间不看中途结果下结论（偷看会放大误判概率），到预设样本量和周期再读数。

## 7. 统计显著性判断

- 双侧检验，显著性水平 α = 0.05：**p < 0.05 且指标差值的 95% 置信区间不跨 0**，才算显著。
- 样本量没跑够就不读结论，结果标"无统计功效"，不能说"没差异"。
- 主指标显著为正 → 全量；显著为负 → 不上线，复盘原因；不显著 → 不上线（不要用"趋势向好"给自己找台阶）。
- 分新老用户等层级做下钻分析，但层级结论视为探索性发现，需另行实验验证。

## 8. 止损条件（硬规则，必须有）

出现以下任一情况，**立即暂停实验组并回滚旧首页**，不等实验结束：

| 护栏指标 | 止损阈值（待你按业务定，参考常见做法） |
|---|---|
| 崩溃率 / 白屏率 | 相对对照组上升 ≥ 20%，或连续 2 天超出【待填】绝对值上限 |
| 主转化指标 | 相对下降 ≥ 5% 且持续 2 天 |
| 首页跳出率 | 相对上升 ≥【待填】个百分点 |
| 客诉 / 退款 | 出现与新首页明确相关的集中投诉，立即人工介入 |

## 9. 埋点与发布

- 上线前核验埋点：首页曝光、分模块曝光与点击、后续转化漏斗全链路事件，AA 阶段用真实数据验证事件不丢不重。
- 发布顺序：AA 验证 → 5% 灰度观察 1 天 → 50/50 正式实验 → 达标后全量。
- 回滚方案：配置开关一键切回旧首页，不依赖发版；回滚责任人【待填】。
